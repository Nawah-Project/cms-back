# Permanent member deletion

Administrators can preview a USER account with `GET /admin/users/:id/deletion-preview`, then delete it with `DELETE /admin/users/:id` and `{ email, confirmation: "DELETE_PERMANENTLY" }`. Both routes require the existing JWT/admin guards. Self-deletion and ADMIN accounts are rejected. The email must match the target. Preview exposes counts, not private storage keys.

A serializable transaction removes related account data, including CV versions, OAuth identity, applications, journey/tour progress, tasks, feedback, email logs, UX events and observations. Non-relational audit identifiers and experiment audience IDs are purged too. Audit writes serialize with deletion and reject missing identities so delayed events cannot recreate a deleted member's audit records. Access tokens check account existence; refresh tokens already do so. Registration with the same email creates a new UUID and fresh progress.

Private-file deletion is a durable outbox: storage keys enter `cv_deletion_jobs` in the same transaction. Cleanup unlinks files immediately and retries pending work every 30 seconds and on startup. Missing files count as success. Strict UUID PDF keys prevent path traversal; files still referenced by another account are retained. A response with `cvFilesPending > 0` must display deferred cleanup rather than claiming all files were removed. The queue contains no account identity or document contents. This removes live application data; historical infrastructure backups are governed separately by their retention policy.

Validation on an isolated synthetic database: all 173 backend tests; 22 API checks covering authorization, incorrect confirmation, rollback, actual files and cascades, shared-file protection, old-token rejection, late events and same-email registration; an actual API restart followed by successful recovery of deferred file cleanup. Browser checks covered cancellation, typed confirmation, a failed DELETE followed by retry, Arabic desktop and English mobile, and verified physical file deletion afterwards. No production member was deleted during release verification.
